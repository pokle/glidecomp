# CLAUDE.md — the GlideComp app

The native iOS and Android app: Expo on React Native, built in the stages of
[docs/2026-10-05-mobile-app-plan.md](../docs/2026-10-05-mobile-app-plan.md),
to the information architecture in
[docs/2026-09-22-ios-app-information-architecture.md](../docs/2026-09-22-ios-app-information-architecture.md).
The root `CLAUDE.md` still applies; this file says how its rules carry over and
what is different here.

## Commands

Run from `mobile/` (or `bun run --cwd mobile <script>`):

| Command | Does |
|---|---|
| `bun run ios` | Build and run on the iOS simulator (`-- --device "iPhone 18 Pro"` to pick one) |
| `bun run android` | Build and run on the Android emulator |
| `bun run start` | Metro only, for a dev build that is already installed |
| `bun run test` | Jest (unit and component) |
| `bun run typecheck` | `tsc` over the app |
| `bun run e2e` | Maestro flows in `.maestro/`, against a booted simulator with the app installed |

From the root, `bun run test:mobile` and `bun run typecheck:mobile` run the
same; both are part of `test:all` / `typecheck:all`, so CI runs them.

Every entry point runs `prepare-sources` first: the engine's scoring
fingerprint, and `scripts/bundle-engine-sample.ts`, which writes the engine
check's sample into `src/engine-check/sample.generated.ts` (gitignored). Call a
tool directly (`bunx jest`, `bunx tsc`) and you skip that — run
`bun run prepare-sources` once first.

`ios/` and `android/` are generated by `expo prebuild` and gitignored
(Continuous Native Generation). Native configuration goes in `app.config.ts`
or a config plugin, never in those folders.

**The Android build needs JDK 17** (`JAVA_HOME`) and `ANDROID_HOME`; see the
plan's stage 0 for the Mac's setup.

### When the simulators misbehave

- **`expo run:ios` builds and installs, then fails on `osascript ... System
  Events`.** The CLI asks System Events whether the Simulator app is running,
  which needs the terminal to hold macOS Automation permission (System
  Settings → Privacy & Security → Automation). Without it, launch the
  installed build yourself: `xcrun simctl launch <udid> com.glidecomp.app`,
  with Metro running (`bun run start`).
- **Android: "Unable to load script", and Metro never sees a request.** The
  emulator can come up with its Wi-Fi network's routing table missing, so
  nothing — Metro on `10.0.2.2`, or the internet — is reachable ("Network is
  unreachable" from `adb shell toybox nc -z 10.0.2.2 8081`). Turn the emulated
  Wi-Fi off and traffic goes over the emulated cellular link, whose table is
  intact: `adb shell svc wifi disable`.
- **Metro started with `CI=1` does not watch files**, so edits never reach the
  app. Run it without.

## Layout

- `src/app/` — Expo Router routes. `(tabs)/` holds the four tabs; each real
  tab is its own native stack. `submit.tsx` is the Submit sheet, presented over
  the tabs from the root stack. Route shapes follow the website's URLs, so
  universal links (stage 9) map one to one.
- `src/components/` — shared components.
- `src/engine-check/` — stage 1's on-device proof that the engine runs.
- `.maestro/` — end-to-end flows.

## The monorepo, and bun's isolated installs

Bun installs each workspace's dependencies in isolation (`node_modules/.bun`),
pnpm-style. That is what lets the app run React 19.3 (pinned by Expo SDK 58)
while the website stays on its own React. **Do not try to make them share
one copy** — React Native refuses to run unless `react` exactly matches its
renderer.

Three consequences, all already handled; keep them when editing the configs:

- **`@babel/runtime` is a direct dependency** of the app. Babel injects
  imports of it into every compiled file, and nothing hoists it any more.
- **Engine files resolve from `web/engine/`**, which has no `@babel/runtime`.
  `metro.config.js` (`resolver.nodeModulesPaths`) and `jest.config.js`
  (`modulePaths`) both fall back to the app's `node_modules`.
- **Jest's `transformIgnorePatterns` exempts `.bun`**, exactly as jest-expo
  exempts pnpm's `.pnpm`; otherwise nothing in the store is compiled.

## The engine on the phone

`@glidecomp/engine` is imported unchanged. Where it reaches for a platform API
Hermes lacks, the app passes an implementation in rather than changing the
engine:

- `parseXCTaskAsync(content, inflateXctskz)` — Hermes has no
  `DecompressionStream`; `inflateXctskz` uses `fflate`.
- Time zones go through `Intl.DateTimeFormat`, which Hermes supports. Always
  pass the comp's zone (`timezoneForXctsk`), never the phone's.

The engine never changes for the app's sake. If Hermes ever needs an engine
change, it is a scoring change like any other and owes a note in
`web/engine/scoring-changes/`.

## Tests

- **Jest + React Native Testing Library 14.** RNTL 14's `render` is
  asynchronous: `await render(...)`. A component that reads the navigation
  theme needs a `ThemeProvider` around it in the test.
- **Maestro** for journeys, on both simulators. Maestro's `back` is
  Android-only; dismiss an iOS sheet with a swipe down (see `.maestro/tabs.yaml`).

## The root rules, as they apply here

| Rule | In the app |
|---|---|
| Australian English; propose UI wording first | Unchanged. Every stage lists its new copy for approval in the PR. Placeholder copy (`StageNote`) is temporary and replaced by the stage named in it. |
| Decisions explainable; the report card's rules (a)–(d) | The engine's explainers, unchanged; GAP parameters from the published `ClassScore.gap_params`; emphasis charts only; the cleaning chart from the downloaded tracklog. |
| Registration is never guessed | The submit sheet resolves through `POST /api/comp/:comp_id/registration/resolve` and asks; `409 identity_ambiguous` means ask again. Names only order the picker. |
| Every submission emails the pilot | The sheet says so up front; the server sends it. |
| Audit log; score staleness | Server-side, so the app inherits them. A new route the app needs follows the same "part of done" rule. |
| A failure to ask is not an answer (#481) | The transport retries transient failures and never records one as "signed out" or "not found". A 4xx is a real answer. |
| A dead link is a searchable one | Universal links use the `${slug}-${id}` shapes; an unresolvable one opens the not-found screen, which uses `GET /api/comp/lookup`. |
| Mobile first; one way to do a thing; a sheet dismisses with Back | Native by construction: system Back and swipe-down dismiss sheets. |
| Altitudes in the reader's unit; radii metric; zero is never missing | The shared `units` module. Waypoint editing stays metric. |
| Never inline geo maths | The engine's `geo.ts` only. |
| Map interaction spec | `@rnmapbox/maps` implements `docs/mapbox-interactions-spec.md`; touch-only differences are written into the spec. |
| Accessibility (WCAG 2.2 AA) | VoiceOver and TalkBack labels, Dynamic Type and font scaling, 44 pt targets, contrast. Audited every stage. |

## Which API a build talks to

There is no staging environment. A development build talks to the local
workers (`bun run dev:workers` on `:8790`; the Android emulator reaches it as
`10.0.2.2`), or to glidecomp.com **read-only**, with writes blocked in the
transport. Only preview, beta and store builds write to production. (The
transport arrives in stage 2.)
