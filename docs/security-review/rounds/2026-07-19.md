### Executive summary

**One new Medium, fixed inline; one new Low, documented.** The Medium — **SEC-30, an open redirect** — is in freshly-added sign-in code (#346/#349): `safeNext()` in `SignIn.tsx` allowed any `next` that starts with a single `/`, but browsers (and the WHATWG URL parser) fold a leading `"/\"` into `"//"` for http(s), so `next=/\evil.example` passed the guard and then resolved to `https://evil.example/` when assigned to `window.location.href` — turning the sign-in page into a phishing bounce (and, for an already-signed-in visitor, a zero-interaction redirect via the `useEffect` at load). **Fixed this PR** by replacing the string-prefix guard with a shared `safeNext()` helper (`web/frontend/src/react/lib/safe-next.ts`) that resolves `next` against a throwaway origin with the same parser the browser uses and rejects anything that lands off-origin, returning only a normalised same-origin path; the duplicate guard in `lib/user.tsx` (`goToSignIn`) now calls the same helper. A 6-case regression test (`safe-next.test.ts`) pins the backslash bypass, protocol-relative/absolute/`javascript:` rejection, and same-origin pass-through. The new Low — **SEC-31** — is that Field Analysis caps the field at `MAX_FIELD_ANALYSIS_TRACKS = 80` by **count**, not bytes; ~80 tracks each near the 2 MiB decompressed IGC ceiling parse into enough `IGCFix` objects to risk the isolate's memory budget. It is admin-gated and runs in `waitUntil` (a failure is caught, stored as the row's `error`, and served — not a user-facing 500 or a cross-user surface), so it is Low and deferred. **Everything else came back clean.** The new authentication path is well-built: OTPs are hashed at rest, three independent rate-limit layers (per-code / per-IP on `cf-connecting-ip` / per-email atomic upsert) box in both interactive and distributed abuse, the send path silently drops over-cap requests to avoid an inbox-existence oracle, and the auto-derived username can only ever be `[a-z0-9-]{3,20}`. Field Analysis's endpoints are admin-only, its store is parameterised and lease-locked, and its engine is bounded (80-track cap + 14 h grid cap + 2 MiB IGC cap + linear/two-pointer sweeps). The IGC-validator rewrite keeps all four SEC-04/SEC-11 checks. `bun audit` clean; every prior fix intact, no regressions.

### New findings

#### SEC-30 — Open redirect via backslash-folded `next` in the sign-in page — **Medium** — ~~Open~~ **Fixed (2026-07-19, this PR)**

> **Resolution:** replaced the string-prefix guard with a shared `safeNext()` (`web/frontend/src/react/lib/safe-next.ts`) that resolves `next` against a throwaway origin via `new URL(raw, base)` and rejects anything whose resolved `.origin` differs (absolute URLs, `//host`, `/\host`, non-http schemes), returning only `pathname+search+hash`. `SignIn.tsx` and `lib/user.tsx` (`goToSignIn`) both call it. Regression test `safe-next.test.ts` (6 cases) pins the bypass closed. Verified: `node -e 'new URL("/\\evil.example","https://x.invalid").origin'` → `https://evil.example`, now → fallback `/comp`.

- **Files:** `web/frontend/src/react/pages/SignIn.tsx:28-31` (old `safeNext`), used at `:66` (`window.location.replace(next)`) and `:92` (`window.location.href = next`); duplicate guard at `web/frontend/src/react/lib/user.tsx:117-118`.
- **Evidence:** the guard was `raw.startsWith("/") && !raw.startsWith("//") ? raw : "/comp"`. `next=/\evil.example` starts with `/` and does **not** start with `//`, so it passed unchanged. Browsers and the WHATWG URL parser fold a leading `/\` into `//` for special (http/https) schemes: `new URL("/\\evil.example", "https://glidecomp.invalid").origin` → `https://evil.example`. Assigned to `window.location.href`, it navigates cross-origin. Confirmed at the tool level (`node` URL check) before fixing.
- **Impact:** a link `https://glidecomp.com/signin?next=/\attacker.example` sends the victim off-site — after a successful OTP/Google sign-in (`verify()` → `:92`), or **immediately with no interaction** if the visitor already has a session (`useEffect` at `:66`). Turns a trusted origin into a phishing/malware bounce. No token leak (the OTP rides the URL fragment and is consumed + stripped before redirect; the session cookie stays same-origin), so Medium not High. Google-OAuth `callbackURL` is separately validated server-side by Better Auth `trustedOrigins`, so the exploitable sink is the client `window.location` assignment.
- **Remediation:** done inline (see resolution). The URL-parser approach is bypass-resistant by construction — it uses the exact parser the browser will use to resolve the value.

#### SEC-31 — Field-analysis field cap is by track count, not decompressed bytes — **Low** — Open (documented)

- **Files:** `web/workers/competition-api/src/scoring.ts:1170` (`MAX_FIELD_ANALYSIS_TRACKS = 80`), enforced at `:1245`; the field accumulates in `flights` at `:1288-1308` and is held alongside the per-pilot detector outputs + shared time grid in `buildFieldContext`.
- **Evidence (subagent):** the cap bounds the *number* of tracks (80), and the resample grid is separately capped (`resample.ts` `MAX_GRID_HOURS = 14`), but nothing bounds total decompressed bytes / fix count. Each IGC is capped at 2 MiB decompressed (~50–60k `IGCFix` objects); 80 near-ceiling tracks parsed into objects (Date + numbers) can approach/exceed the isolate's ~128 MB budget — the exact memory pressure the `wrangler.toml [limits]` comment names as "the real limit for field analysis".
- **Impact:** an isolate OOM during a cold field-analysis compute. Mitigations that keep this **Low**: the compute is admin-gated (only `canViewFieldAnalysis` callers schedule it) and runs in `waitUntil` (background) — an OOM there fails the background job, which `computeAndStoreFieldAnalysis` catches and stores as the row's `error` (served to the admin, then it stops retrying), not a user-facing 500 or a cross-user surface. Real IGCs rarely approach the pure-B-record 2 MiB worst case. Not exploitable by an anonymous or non-admin caller.
- **Remediation (next round):** cap on estimated total fixes/bytes (sum of stored `igc_size` or a running fix-count budget) rather than track count, and/or lower the per-track ceiling for the analysis path; add a test asserting a synthetic 80×large field is refused with a `FieldAnalysisUnsupported` rather than OOMing.
