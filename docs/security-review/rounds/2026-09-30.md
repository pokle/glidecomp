### Executive summary

**The worst new finding is SEC-52: `bun audit` regressed from 0 to 18
advisories (4 high) in the week after it first read clean** — the third
instance of the G-20 pattern (newly-disclosed CVEs against already-locked,
range-satisfying versions; SEC-48, SEC-50). All are transitive through the
`shadcn` devDependency chain or miniflare/wrangler (dev/build/test-time, none
in a deployed Worker bundle). Fixed inline by raising four `overrides`
(`undici`, `fast-uri`, `brace-expansion`) and adding one (`ip-address`); audit
is clean again. The big auth change in this window — trusting a
JWKS-verified session cookie instead of calling auth-api — was read in full
and is sound: asymmetric verification with key-pinned algorithm, `typ`/`aud`
binding, claim-consistency checks, and a fail-open-to-the-authority fallback.
Its one trade-off (up to five minutes' lag on a revoked session) is by design
and recorded as SEC-54. No Critical findings.

### New findings

#### SEC-52 — `bun audit` regression: undici/fast-uri/ip-address/brace-expansion — **Medium, fixed inline**

**Files.** `package.json` (`overrides`), `bun.lock`.

**Evidence.** 18 advisories: `undici 7.29.0` (4 incl. 2 high: TLS validation
bypass in `BalancedPool`, unrequested-subprotocol WebSocket DoS) via
`miniflare`/`wrangler`/`@cloudflare/vitest-pool-workers`; `brace-expansion
5.0.9` (2 high, stack-exhaustion DoS) via `shadcn → ts-morph → minimatch`;
`fast-uri 3.1.7` via `ajv`; `ip-address 10.4.0` via `express-rate-limit`/
`socks`. The existing overrides (`^7.29.0`, `^5.0.8`, `^3.1.6`) were satisfied
by the locked versions, so nothing forced re-resolution.

**Impact.** Dev/build/test-time only; no runtime Worker imports these. Risk is
to developer machines and CI processing hostile input.

**Remediation (applied).** `undici ^7.29.1`, `fast-uri ^3.1.8`,
`brace-expansion ^5.0.11`, new `ip-address ^10.5.1`; `bun install`; `bun audit`
→ "No vulnerabilities found". Full `typecheck:all` and `test:all` green.

#### SEC-53 — `/api/csp-report` reads the body before enforcing its cap — **Low, open**

**Files.** `functions/api/csp-report.ts` (`onRequestPost`).

**Evidence.** The 64 KB cap checks `Content-Length`, defaulting to 0 when the
header is absent, then calls `request.text()`. A chunked upload has no
`Content-Length`, so the declared-size check passes and the whole body is
buffered before the post-read length check rejects it.

**Impact.** Unauthenticated, but bounded by the platform's own request-body
ceiling and the Function's 128 MB memory; worst case is wasted CPU/memory per
request, not data exposure. Log volume is capped at 20 lines per request with
300-char fields.

**Remediation (proposed).** Read through a size-limited stream
(`request.body` reader that aborts past the cap), or reject a request with no
`Content-Length`.

#### SEC-54 — Session revocation lags by up to 5 minutes at competition-api and the SSR pages — **Info, accepted by design**

**Files.** `web/workers/auth-api/src/auth.ts` (`SESSION_CACHE_MAX_AGE_S`),
`web/workers/shared/src/session-cookie.ts`.

**Evidence / impact.** A `session_data` cookie vouches for a browser until it
expires; a session revoked or signed out on another device keeps working at
competition-api until then. The code documents this. Account deletion, which
is irreversible, deliberately reads D1 and expires both cookies.

**Remediation.** None needed. Re-evaluate only if a competition-api route
ever gains an action comparable to account deletion (then read D1 for it too).
