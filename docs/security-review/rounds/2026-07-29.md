### Executive summary

**Two Lows fixed inline (one new, one long-carrying), no Critical/High/Medium, no new `bun audit` advisory, all prior fixes intact.** The window's largest new surface — the CIVL world-rankings import (#512) — is built the way this codebase's other external-data ingestion is: the fetch target is hardcoded, not request-derived; the untrusted response is structurally validated (zip magic bytes, a footer row-count assertion, duplicate-id detection) before anything reaches D1; the trigger is a GitHub Actions cron/dispatch, never a public HTTP endpoint; and even though the SQL is CLI-generated string SQL rather than a `.bind()` call (the only option available to a script driving `wrangler d1 execute`), every string value is quote-escaped and every numeric value is type-validated before use. The one new finding, **SEC-36 (Low)**, is that its companion public read route, `GET /api/civl-rankings.csv`, wrote CSV cells with RFC-4180 quoting only — no protection against a cell like a pilot's name starting with `=`/`+`/`-`/`@`, which Excel/Sheets reads as a formula the moment the downloaded file is opened. This is the same vulnerability class as the long-open **SEC-28** (the admin pilot-import/export CSV), and reviewing them together made the fix obvious and cheap: the pattern was already correctly implemented and tested in this window's *other* new CSV writer (`scores-csv.ts`), so both `civl-rankings.ts`'s `csvCell()` and `csv.ts`'s `csvEscape()` now get the same `'`-prefix guard on a leading `=+-@`/tab/CR, and `csv.ts`'s importer strips that guard back off so re-importing our own export doesn't accumulate stray quotes. Both are fixed inline this PR with regression tests. Elsewhere: the `scoring.ts` diff was purely additive read-side computation with no new mutation path, so the audit-log/stale-score-bump rule had nothing new to check; the report-card build-out (validity sparklines, distance distribution, glossary, scores, track-cleaning and scoring-curve charts, ESS arrival order) was checked against all four report-card rules in CLAUDE.md and found compliant on every one; and gap #12 — the frontend test suite's long-standing exclusion from `test:all` — turned out to have already been closed by an unrelated CI-infrastructure commit (#511), so it's removed from the gap list this round.

### New findings

#### SEC-36 — CSV formula injection in the new `civl-rankings.csv` route — **Low** — ~~Open~~ **Fixed (2026-07-29, this PR)**

- **Files:** `web/workers/competition-api/src/routes/civl-rankings.ts` (`csvCell`).
- **Evidence:** `GET /api/civl-rankings.csv` streams the `pilot_ranking` table (imported verbatim from civlcomps.org — see SEC-36's sibling section above) as an `attachment` download, explicitly meant to be opened in Excel/Sheets. Its `csvCell()` applied RFC-4180 quoting (comma/quote/CR/LF) only — a `pilot_name`, `ranking_name`, `region`, `selection`, or `nation` value starting with `=`, `+`, `-`, or `@` was written verbatim, which Excel/Sheets/LibreOffice interpret as a formula (or, via `=WEBSERVICE()`/`=HYPERLINK()`, a data-exfiltration or drive-by vector) the moment the file is opened. Same class as the long-open SEC-28.
- **Impact:** the route is public and unauthenticated, and the field data (pilot names, nation, list metadata) comes from an external source (CIVL's own export) rather than from GlideComp's own input validation, so a typo, a deliberately-named pilot, or a compromised upstream feed could carry a formula trigger through to anyone who downloads and opens the CSV. **Low**: requires the victim to open the file in a spreadsheet app with formula execution enabled (the modern default in Excel/Sheets for CSV imports is to prompt or disable auto-calc for external content in some versions, but this varies), and CIVL's own naming conventions make a hostile pilot name unlikely; no server-side or authz impact.
- **Resolution:** `csvCell()` now prefixes a value with `'` before quoting whenever it starts with `=`, `+`, `-`, `@`, a tab, or a CR — mirroring the pattern already implemented and tested in this window's `scores-csv.ts`. Regression test added to `test/civl-rankings.test.ts` ("guards a formula-looking name against CSV/DDE injection").
